# SIMIND v8/v9 validation inventory

- **Already present:** engine output prefixes are capped at 47 characters; up to 99 numbered windows and exact `tot`/`sca`/`pri`/PENETRATE component names are loaded from matching headers; byte offsets and full-pixel payload sizes are checked; measured geometry and source/mu-map grids are checked; DICOM diagnostics, container library isolation, and validation scripts have focused coverage.
- **Ported:** generated `.win` prefixes are capped at 15 characters, and a window file cannot silently follow a changed output prefix; example 02 now uses safe prefixes. This cap does not apply to runtime `FW`: a v8 raw-engine check read two requested windows from a 16-character `FW` filename. The connector preserves the caller's `/CA` selection and derives the missing order-0 scatter or primary image only when compatible output headers exist. Executor timeouts are exposed through core, native, and PyTomography runs.
- **Ported:** reject non-finite or fractional Interfile byte offsets and payloads ending in a partial pixel; complete extra/short pixels are also rejected.
- **Ported:** SIMIND v9 PENETRATE `.hNN` headers are converted alongside their matching `.bNN` payloads. SIMIND v8's shared `.h00` template remains supported. Unknown component 20 is exposed as `b20` without assigning it an inferred physical label.
- **Version selection and centring:** `simind_version=8|9` is available on core/native/PyTomography constructors; `SIMIND_VERSION` supplies the default when omitted, and v8 is the fallback. SIMIND v9's manual records its image-map origin correction. Matching v8/v9 runs used byte-identical source and density arrays, while the `.res` center changed from I/J=9 to 9.5 for a 16³ map. Analytic point-source probes established the corresponding transverse source shift and density-map origin offsets. The connector applies the measured shifts only to a copied v9 voxel-run `.smc`: source Indexes 17/18 use effective `PX`, density Indexes 36/37 use Index 31. It rejects non-default `DI`, density Index 32, or `OR` orientations because those correction mappings have not been validated.
- **Measured-geometry smoke:** the existing four 16³/eight-view SIRF geometry cases passed on v9 Linux Intel after origin compensation without changing their thresholds: CW gap/correlation 0.39 bins/0.660; CCW 0.48/0.674; non-circular 0.46/0.672; anisotropic 0.64/0.538. All are explicitly low-history smoke results.
- **MPI normalization:** the matching v8 and v9 serial, two-rank replicate, and two-rank split tests passed the existing 5% tolerance at 24 views, 32³ maps, 512 active voxels and `quantization_scale=0.05×DEFAULT`. V8 serial/replicate totals were 1602.64343 and split was 1630.26123 (+1.72%); v9 serial/replicate were 1616.91553 and split 1601.95117 (−0.93%). These are per-build normalization checks, not a cross-version accuracy comparison.
- **Smoke evidence:** SIMIND V8.0 Linux Intel build compiled 2025-10-06 and V9.0 Linux Intel build compiled 2026-10-08 both ran 16³ centered-point, uniform-attenuation, four-view low-history core cases. V8 SCATTWIN `/CA:0` writes `tot`; `/CA:1` and `/CA:2` write `air/sca/tot`, with `/CA:2` also writing a raw primary header. V9 `/CA:0` writes `tot`; `/CA:1` writes `air/tot`; its Linux Intel `/CA:2` process aborts with `free(): invalid pointer` after writing payloads but before headers. The native macOS ARM64 V9.0 build completes `/CA:2` and returns `ai2/air/pri/sca/tot`. The connector leaves that engine failure visible.
- **MPI smoke evidence:** matching v8 and v9 Linux `simind_mpi` binaries both completed two-rank, projection-split SCATTWIN runs with four views. Their low-history totals are smoke results, not a quantitative cross-version comparison.
- **Reviewed math:** the attenuation tables use MeV and cm²/g. The loader divides input keV by 1000 for interpolation, then multiplies the mass attenuation coefficient by density to obtain cm⁻¹. At 140 keV the checked values are water 0.15454 cm⁻¹ and bone 0.287342 cm⁻¹ at densities 1.0 and 1.85 g/cm³. HU values −1000/0/+1000 map to air/water/bone. Index 25 carries MBq×seconds per projection; source-map values control histories and remain separate from absolute activity. Both engines passed exact binwise activity and acquisition-time doubling checks. An exploratory v8 water/air PENETRATE ratio was 0.6081 versus center-path Beer–Lambert 0.6188 for a 16³, 4 mm point source. Monte Carlo uncertainty was not quantified for that check; it does not establish quantitative calibration.
- **Reviewed geometry/reconstruction:** source and attenuation images must share shape, finite positive voxel sizes, origin, and a native direction matrix where the backend exposes one. Measured-geometry SIRF/reconstruction regressions pass. In the SIRF 3.10.1/STIR 6.4 cache regression, disabling all-views caching reduced first-update residual discrepancy from 0.0222821 to 1.55e-6.
- **Complete workflow smokes:** the same 96³ NEMA phantom at 4 mm, 568.1 MBq, four views, `NN=1`, and `quantization_scale=0.01×DEFAULT` completed with both STIR and SIRF on v8 and v9 Linux. Both backends produced finite 96³ reconstructions; projection totals were approximately 66,190 (v8) and 67,500 (v9). A reduced v8 SIRF scatter-correction run completed one refresh with scale 2019 and scatter sum 2.321×10⁵; its contrast error was 7.8% both with and without correction. These smoke runs do not establish quantitative accuracy or an improvement in reconstruction quality.
- **Other backend evidence:** SIRF 3.10.1 uses STIR 6.4.0. PyTomography 3.4.0 with torch 2.14.1+cpu completed reduced Example 07C on both Linux engines: four views, 32³ images, `NN=1`, and `quantization_scale=0.01×DEFAULT`, producing finite nonzero reconstructions. The selected backend tests passed (SIRF geometry/reconstruction 66; STIR 3; PyTomography 31). Both supported real-engine regression runs passed 13 tests, on v8 Linux and v9 macOS ARM respectively.
- **Core and packaging evidence:** 1,148 local core tests passed; the rebuilt core container passed 1,146 tests plus three import-isolation checks. Ruff, strict offline Sphinx, wheel/sdist resource checks, and `uv lock --check --offline` passed. Build tools are declared in the dev extra, and Compose forwards explicit version selection to all services.
- **Remaining quantitative gates:** calibrated absolute detector sensitivity, sufficient-history attenuation and reconstruction comparisons with uncertainty estimates, and measured-data calibration remain outside the evidence above. Full release validation must establish those references and tolerances before making quantitative claims.
- **Excluded:** release-1.2.0 architectural rewrites, backend/API removals, and legacy release automation unrelated to SIMIND v8/v9 correctness.
